# SystolicGuard 设计说明与答辩提纲

## 1. 项目目标

SystolicGuard 实现一个面向神经网络推理的 2×2 INT8 矩阵乘法加速器。重点不是搭建完整 NPU，而是展示 AI 芯片最核心的并行乘加、数据流和低精度推理。

```text
C[i][j] = sum(A[i][k] × B[k][j]), k=0..1
ReLU(x) = max(0, x)
```

## 2. 数据格式

| 数据 | 位宽 | 原因 |
|---|---:|---|
| 激活值 A | signed INT8 | 模拟量化网络输入 |
| 权重 B | signed INT8 | 模拟量化模型权重 |
| 乘积 | signed INT16 | 两个 INT8 相乘 |
| 部分和/输出 | signed INT32 | 防止多项累加过早溢出 |

INT8 不代表中间结果也只能有 8 位。乘法和累加使用更宽的数据，是定点推理硬件的重要原则。

## 3. PE 与数据流

每个 Processing Element 包含一个有符号 8×8 乘法器、一个 32 位累加寄存器和两组数据传递寄存器。

本设计采用 output-stationary 数据流：每个 PE 固定保存一个输出元素的部分和；A 向右流动，B 向下流动。

```text
             B col 0       B col 1
                │             │
                ▼             ▼
A row 0 ───► [ PE00 ] ───► [ PE01 ]
                │             │
                ▼             ▼
A row 1 ───► [ PE10 ] ───► [ PE11 ]
```

## 4. 数据错位调度

第二行 A 和第二列 B 延迟一个周期注入，使正确的激活与权重在正确时钟到达同一个 PE。

| COMPUTE 周期 | row0 | row1 | col0 | col1 |
|---:|---:|---:|---:|---:|
| 0 | A00 | 0 | B00 | 0 |
| 1 | A01 | A10 | B10 | B01 |
| 2 | 0 | A11 | 0 | B11 |
| 3 | 0 | 0 | 0 | 0（排空） |

最后一个排空周期让 A11 和 B11 到达最远端的 PE11。

## 5. 控制状态机

```text
IDLE → PREP → COMPUTE → ACTIVATE → DONE → IDLE
```

- `IDLE`：写输入和权重缓冲，等待 `start`。
- `PREP`：清空 PE 流水寄存器和累加器。
- `COMPUTE`：用 4 个时钟完成注入、计算与排空。
- `ACTIVATE`：执行 ReLU 或旁路，写输出缓冲。
- `DONE`：产生一个时钟周期的完成信号。

从 PREP 到结果写回需要 6 个内部周期，`cycle_count` 保留该结果。

## 6. 验证方法

测试平台会自动比较硬件结果与预期值，覆盖基本矩阵乘法、signed INT8 负数、ReLU 和 bypass。另有 Python 黄金模型，避免验证只依赖 RTL 测试代码。

## 7. 答辩时可强调

1. **为什么用 INT8**：减少存储、带宽和乘法器成本，适合推理。
2. **为什么累加器用 INT32**：INT8 乘法产生 INT16，多项累加需要额外位宽。
3. **为什么需要错位输入**：让成对数据在同一周期到达对应 PE。
4. **为什么叫 output-stationary**：部分和留在 PE 内，减少其反复搬运。
5. **为什么加入 ReLU**：矩阵核心后直接连接激活单元，形成小型推理流水线。
6. **边界是什么**：这是教学型计算核心，不宣称是完整商用 NPU。
